# 球群当晚：排场、小比赛和收款（计划放进 iPhone 1.0.8）

2026-11-18 用户同意的顺序：1.0.7 做访客报名（`GUEST_SIGNUP.md`），1.0.8 做这一份。还没开工。

## 为什么做

冷启动时要有“一个组织者自己就能用”的东西。羽毛球的俱乐部之夜现在大多靠挂牌板决定下一场谁上，打完再在群里一个个收场地费。这两件事每周都发生，组织者一个人就能用起来，球员不用装 App。匹克球那边做排场的 App（PB Play、Picklr 等）评价很好；美国的羽毛球 App Shuttlers 在主打收款。调研见宣传仓库的说明。

做完以后给组织者的一句话：报名、候补、排场、收钱，一个链接，球员什么都不用装。

## 界面放在哪：不加标签、不加菜单项（用户 2026-11-18 定的前提）

用户要求：加了排场、循环赛、收款以后界面不能显得臃肿，能保证这一点就不删现有功能。做法：

1. **新东西都放在“某一场”里面，只给组织者、只在当天出现。** 不加底部标签，不加“+”菜单项，不在球局页加新的一块。
2. 组织者在球群页的场次行上，开场前 1 小时到结束时多一个按钮“开始今晚”，点进去是“今晚”页，顶部分段：**排场 | 比赛 | 收款**。三样共用同一份到场名单。
3. 球员和访客不进这一页，只看公开看板（链接 / 二维码）。
4. 收款方式填在“我的 → 收款方式”，平时不出现在别处。
5. 顺带：球局页现有的几块（本周排行、同馆常客、附近球局等）没有内容时整块不显示，不放空状态。只是不显示，不删功能。

```
球群页 · 周三 7–10 PM  LABC       今晚 · 周三 7–10 PM
┌────────────────────────┐        [ 排场 | 比赛 | 收款 ]
│ 已报 18/20 · 候补 2     │        场地 1  A B / C D   12'  [打完了]
│ [开始今晚]  （组织者）   │  →     场地 2  E F / G H    4'  [打完了]
└────────────────────────┘        接下来  I J / K L
                                   等候    M · N · O（今晚各 2 场）
                                   [二维码]           [+ 加人]
```

## 一、场边排场（电子挂牌板）

**入口**
- 只从球群的某一场进入（“开始今晚”）。到场名单预先填好：报上名的成员和访客。
- 不单独做“临时排场”入口：还没用球群的组织者先建一个群（访客报名让这一步很轻），避免多一个入口。

**设置**（一屏）
- 几片场地（1–12），单打或双打（默认双打）。
- 到场的人：点名字切换“到了 / 休息 / 走了”；随时加名字（访客，不用账号）。
- “按水平分队”开关：有等级的人按等级配平；没等级的访客按中间水平算。

**排的规则**（服务器算，所有人看到同一份）
- 有空场地就从等的人里挑：先挑今晚上场次数最少的，一样多的挑等得最久的。
- 双打尽量不和刚搭档过的人再搭；同一组四个人尽量不连着重复。
- 组织者可以手动改：把某人放到下一场、换人、跳过。手动的优先。

**场上**
- 每片场地一张卡：场上四人、开始了几分钟。点“打完了”，可以填比分（可跳过），四个人回到等候队尾。
- 下面是“接下来”：下两场是谁，加上等候名单和每个人今晚打了几场。

**大家看**
- 一个网页链接和二维码（不用登录），显示场地、下一场、等候名单，10 秒刷新一次。组织者可以把二维码立在场边。

**数据**
- 今晚的比分记下来，以后给“个人打球记录”用。v1 不进每周排行（要用户定，见最后）。
- 结束后保留 30 天，组织者能看今晚每人打了几场。

## 二、小比赛（“今晚”页的“比赛”分段）

- 用同一份到场名单，组织者选：循环赛（每人和不同搭档打，按个人胜场和净胜分排名）或分组循环（固定双打组合，组和组打）。场地数沿用排场的设置。
- 自动排对阵和场地，打完填比分，积分榜实时更新；公开看板切到“比赛”时显示对阵和积分榜。
- 比赛进行时，“排场”分段暂停，结束后回到排场。
- 不做淘汰赛表、不做跨晚的联赛。

## 三、收款链接和提醒

**收款方式**（“我的”→ 收款方式，可选，都可以不填）
- Venmo 用户名、Cash App 的 $cashtag、PayPal.me 用户名、Zelle（邮箱或手机号）。
- 只给同一场球局、同一个球群场次的人看；公开网页（访客报名页、排场页）上不显示 Zelle，Venmo / Cash App / PayPal 显示组织者愿意公开的那几个。

**付钱的人看到**
- 球局的 AA 卡、球群场次（填了费用说明的）上有“付给 {组织者}”：点 Venmo / Cash App / PayPal 直接打开对应 App，金额和备注（“Badie · 周三 7 点 · LABC”）预先填好；Zelle 没有链接，只给“复制”。
- 付完点“我付了”，组织者那边变成“已付”（球局沿用 `mark_paid`）。

**组织者看到**
- 球群场次多一个“谁付了”：报名的人（含访客）逐个点成已付；没付的有“提醒”按钮。
- “提醒没付的”：注册用户收推送，留了邮箱的访客收邮件；同一场 12 小时内只能提醒一次。

**注意**
- 钱不经过 Badie，App 只给链接，不处理付款，不抽成。
- 这是线下场地费，不是数字内容，不走苹果内购；提交审核时 Notes 写明（和打赏的说明分开写）。
- 收款信息是个人信息：注销账号时一并删；数据导出里带上。

## 各端

- 数据库：排场（场地、到场名单、每场对阵和比分）、收款方式、球群场次的已付标记；pgTAP 测试覆盖排人规则（场次最少优先、不连着搭档、手动优先）。
- 网站：组织者的排场页、公开的看板页、收款方式设置。
- iPhone 1.0.8、安卓跟上：同样的几样。排场页要能在场边单手用，按钮够大。

## 不做

- 不做淘汰赛表和跨晚的联赛。
- 不在 App 里收钱、不保存银行卡。
- 不做离线：球馆网络差时以后再看，v1 要联网。

## 验收

- 组织者在 iPhone 上对一场 12 人、3 片场地的球群点“排场”，一晚上每人上场次数最多差 1；有人中途来走，下一场马上跟着变。
- 场边的人扫二维码，不登录就看到下一场是谁。
- 打完一局，付钱的人点 Venmo 打开 Venmo 且金额正确；组织者点“提醒没付的”，没付的注册用户收到推送、留了邮箱的访客收到邮件。
