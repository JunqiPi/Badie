# 球群的访客报名（计划放进 iPhone 1.0.7）

2026-11-18 用户定的方向。数据库、网站、iPhone 已做（2026-11-18，做法和比这里简单的地方见 STATUS.md 的“球群的访客报名”），安卓还没跟上。下面“要用户定的”三条都按建议定了；人机验证用 Turnstile 的无感模式。

## 为什么做

冷启动时，组织者想用 Badie 管每周的局，群里二三十人得每个人都下载、注册、选常去球馆才能报名。只要一半人嫌麻烦，组织者就得维护两份名单，很快放弃。

访客报名让**一个组织者第一天就能用**：他把链接发到原来的微信 / WhatsApp 群，球员点开网页、填名字就能报名或候补，不用装 App、不用注册。组织者在 App 里看完整名单。用顺手的人以后再注册。

对外的说法（更新说明、外联私信、推荐提名）：“Run your weekly game without asking everyone to download an app.”

## 用起来是什么样

**组织者**（iPhone、网站）
- 球群设置里一个开关“允许不注册的人报名”，默认关；打开后球群页多一个“复制报名链接”。
- 名单里访客的名字后面标“访客”。组织者可以移出访客（和移出成员一样，候补递补照常）。
- 关掉开关：链接失效，已经报上的访客保留到这一场结束。

**访客**（只有网页，`https://badie.rsvp/g/<群号>/`，9 种语言，不用登录）
- 看到：群名、球馆（多球馆时每场写实际球馆）、接下来 14 天的场次、每场“已报 n/容量”“候补 n”和报名的人的名字。
- 报名：填名字（2–20 字，过不当词过滤），过 Turnstile 人机验证。满了进候补，显示“候补第 n 位”。
- 可选填邮箱：被递补、场次取消时发邮件。不填就只能自己回来看。
- 取消：报名后浏览器记住一个凭证（localStorage），同一台设备上能取消；换设备取消不了，找组织者。邮件里也带取消链接。
- 页面底部一句话介绍 Badie 和下载 / 注册入口。注册后可以把这台设备上的访客报名转成自己的（同一场不重复）。

## 数据和接口（建议）

- `session_signups` 加访客行，不另开表，名额和候补的逻辑只有一份：
  - `user_id` 改成可空，加 `guest_id uuid`、`guest_name text`、`guest_email text`、`guest_token_hash text`；检查约束：`user_id` 和 `guest_id` 恰好一个有值。
  - 主键改成独立的 `id`，加唯一约束 `(session_id, user_id)`、`(session_id, guest_id)`。
- `play_groups` 加 `guests_allowed boolean not null default false`。
- 新函数（`security definer`，给 `anon` 执行权限）：
  - `guest_group_page(p_code)`：只在 `guests_allowed` 时返回上面“看到”的那些字段；注册用户只给显示名，不给 id、头像、等级。
  - `guest_sign_up(p_session, p_name, p_email, p_captcha)` → `confirmed` / `waitlisted` 和取消凭证（明文只返回这一次，库里存哈希）。人机验证在 Edge Function 里核对（网站已有 Turnstile，见 `web/src/app/captcha.ts`），或者整个报名走 Edge Function。
  - `guest_cancel(p_token)`：和 `cancel_signup` 同样的递补逻辑。访客不记“临时取消”（没有账号可记）。
  - `remove_guest(p_session, p_guest)`：组织者用。
- `promote_waitlist`、取消场次、`group_page`、`my_groups` 都要认访客行；给访客的通知走邮件（`send-email`），不走推送。
- 防乱填：每个 IP 每小时报名次数上限；每场访客最多占容量的一半（要用户定）；同一场同名提示“已经有同名的人，确定吗”。

## 各端

- **数据库 + 网站**：大头。迁移、pgTAP 测试、公开页面、9 种语言文字。
- **iPhone 1.0.7**：设置里的开关、“复制报名链接”、名单里的“访客”标记、移出访客。旧版 App 看到访客行不能崩：`group_page` 里访客以 `guest: true` 的形式出现，旧版忽略未知字段，人数照算。
- **安卓**：跟上同样的四样。

## 不做

- 访客不进群聊、不算成员、不进排行榜和同馆常客、不记爽约。
- 不给访客发推送。
- 不做付款。

## 要用户定的（已定：都按建议）

1. 公开页面上显示报名的人的名字吗？（建议显示，组织者和球员都要看谁来；注册用户在隐私设置里可以选只显示名字首字母）
2. 每场访客最多占多少名额？（建议一半，组织者可以改）
3. 链接用群号（6 位，已有）还是另发一个更长的、可以重置的链接？（建议另发：群号是给 App 里加群用的，泄露了只能解散重建）

## 验收

- 没有账号的人用手机浏览器打开链接、填名字，30 秒内报上；满员时进候补，前面有人取消后自动补上，填了邮箱的收到邮件。
- 组织者在 iPhone 上看到访客、能移出；关掉开关后链接打不开。
- 旧版 iPhone App 打开有访客的球群不报错，人数正确。
