# 羽毛球搭子 · Badie (iOS)

按 **水平 · 时间 · 距离** 匹配附近的羽毛球搭子；AA 费用透明、到场签到、双盲互评，让约球更靠谱。

> 设计过程、用户研究证据、设计系统与需求对照见 [docs/DESIGN.md](docs/DESIGN.md)。

## 运行

| 项 | 要求 |
|---|---|
| Xcode | 16 或更新（工程使用“文件夹同步”，新增文件无需手动加入工程） |
| iOS | 17.0+ |
| 依赖 | 无第三方依赖 |

1. 打开 `BadmintonBuddy.xcodeproj`，选择 iPhone 模拟器，`⌘R` 运行。
2. 登录：选择国家/地区（默认跟随设备，首发 +1）→ 输入手机号 → 获取验证码。演示环境不发短信，验证码会显示在页面上，可一键填入。
3. 首次注册会生成一份演示数据（3 位球友、1 条好友申请、私信、附近公开球局、1 场待评价的球局），方便完整体验流程。设置页可“重置演示数据”。
4. 模拟器定位建议设为洛杉矶圣盖博谷（Features → Location → Custom：34.0686, -118.0276），可看到收录的球馆（LABC、Elite Rally 等）。其他城市可以直接搜索 Apple 地图上的球馆，或自己添加；不会再生成虚构的示例球馆。

测试：`⌘U`，或

```bash
xcodebuild test -project BadmintonBuddy.xcodeproj -scheme BadmintonBuddy \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' CODE_SIGNING_ALLOWED=NO
```

CI（`.github/workflows/ios.yml`）在 macOS 上编译、跑单元测试，并用 `-BBDemoScreen <页面>` 启动参数截取浅色/深色共 46 张界面截图（Actions 产物 `screenshots`）。

## 功能

- **球馆（所有人选同一家）**：平台球馆库是唯一标准，匹配只比较球馆 ID。一个搜索框搜名称、简称（LABC）、拼音、地址；每行显示地址与距离；Apple 地图结果先看地图核对、查重再入库；找不到可放图钉添加或粘贴 Google / Apple 地图链接；“已核实 / 球友确认 / 待确认”三级可信度，签到即确认，多人举报才下架。详见 [docs/DESIGN.md §9](docs/DESIGN.md)。
- **全球化**：E.164 手机号（13 个国家/地区）、球馆当地币种与时区、英里/公里跟随设备地区、按国家给出导航 App（美国 Apple / Google / Waze，国内高德 / 百度，韩国 Naver / Kakao）。
- **快速匹配**：单打/双打，14 天内任意 1–8 小时时段，最多 3 个球馆，水平差 ±1/±2/不限；至少重叠 30 分钟，水平优先、距离其次；双打自动按水平平衡分组；无结果时只给出“确实能找到人”的放宽建议。
- **约球请求（后台排队）**：发起后不用盯着屏幕，找到人会通知；所有人都确认才成局，有人来不了双打自动补位、单打重新排队，谁没确认不会公开。普通局开赛前 2 小时锁定；2.5 小时内的临时局只找附近此刻也在找人的球友，5–10 分钟确认。拒绝和超时不扣分，只有确认后爽约/临时取消才计入记录。详见 [docs/DESIGN.md §10](docs/DESIGN.md)。
- **找到搭子**：看到对方的“靠谱”徽章与球友给的正面印象（不显示任何分数），不合适可以“这次不行”。
- **球局**：球局票（倒计时）、Apple 地图 / 高德 / 百度导航、三次本地提醒（1 天 / 2 小时 / 15 分钟）、加入系统日历、开赛前 30 分钟签到、AA 明细与已付标记、开赛前 2 小时内取消计为临时取消、结束并记录比分。
- **发起球局 / 房间**：私密房间（6 位房间码，30 分钟无活动自动关闭）或公开到附近（水平范围、氛围标签、满员候补自动递补）；邀请好友、房主踢人、满员开局。
- **等级（1–9 级 × −/本级/+，共 27 档）**：1–7− 用能观察的动作和喂球计数测验描述（如“吊球 / 推勾 10 个里 6–7 个到位”）。注册时回答 8 道动作题自动定档（最高 7−），设有门槛防止虚高；打满 5 场后按球友评价校准，每 90 天可重测。7 起只凭能查到的证据认证：赛事成绩、USAB 全国排名或运动员等级证书、BWF 世界排名（9+ = 世界排名前 20 等世界顶尖成绩，只有 BWF ID 不够）。详见 [docs/DESIGN.md §13](docs/DESIGN.md)。
- **球群（固定局）**：组织者建群绑定球馆，每周固定场次；一键报名、满员自动候补、有人退出自动递补；群号可以发到微信。不用再在群里接龙。
- **社交与安全**：点任何头像都能看资料（含“你们的交集”）；好友随便聊，同一场球局用球局群聊（赛后 48 小时关闭），同球群只能发一条消息请求，陌生人只能加好友；出现站外联系方式会提示防骗；首页显示“同馆常客”（本人开启才出现），不显示附近的人和在线状态；“想再约”双方都选才揭晓。详见 [docs/DESIGN.md §12](docs/DESIGN.md)。
- **双盲互评**：到场情况、水平三选一校准、球品星级、正面标签、需要注意的地方；双方都提交或 48 小时后才计入；过期不计入、不可重复提交。球品分只用于内部排序，任何人（包括本人）都看不到；正面标签需 ≥5 位球友、≥3 场后才显示并按月刷新；问题只在多人提到时私下提醒。详见 [docs/DESIGN.md §11](docs/DESIGN.md)。
- **等级体系**：27 档；问卷最高 7−，7 起需认证；评价满 5 次后按 30% 问卷 + 70% 球友评价计算，认证后球友评价最多下调 1 档。
- **社交**：好友申请/通过、搜索（昵称或 4 位 ID）、私信（已送达/已读、输入中、快捷回复、1000 字上限）、屏蔽（不通知对方）、举报、删除会话只对自己生效。
- **我的**：资料编辑（本地照片头像）、口碑、履约记录与分级处理、常用时间（最多 5 个）、出行范围、球馆收藏、屏蔽名单、外观（跟随系统/浅色/深色）、退出登录、注销账号。

## 结构

```
BadmintonBuddy/
├── App/            入口、全局状态、路由、主框架、演示启动器
├── DesignSystem/   设计 Token 与组件（Court Pop）
├── Models/         领域模型（用户、球馆、时间段、球局、房间、消息、评价…）
├── Services/       匹配算法、模拟后端、提醒、导航、持久化
├── Managers/       各功能的 ObservableObject（订阅后端事件）
└── Features/       按功能划分的界面
BadmintonBuddyTests/  模型、匹配算法、后端业务规则测试
```

### 关于后端

目前没有线上服务。`Services/Backend/MockBackend` 在本机扮演服务器：JSON 持久化账户与数据，模拟附近球友（有空时间、回复消息、通过好友申请、加入球局、签到、互评），并通过 `BackendEvent` 事件流推送变化。接入真实服务时，只需实现同样的接口与事件，Manager 和界面层不用改。
